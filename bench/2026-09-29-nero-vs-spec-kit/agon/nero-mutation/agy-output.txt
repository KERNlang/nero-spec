## Challenge 1: Generic struct method sets break optional interface segregation
**Framework:** INVERSION
**Failure scenario:** The spec assumes `SchemaItemsTyper` can remain an "optional" interface implemented only by slice flags while declaring generic forwarding methods directly on `FlagBase[T, C, V]` in `flag_impl.go`. In Go, methods cannot be conditionally declared on generic types based on type constraints; every method defined on `FlagBase[T, C, V]` exists on all concrete instantiations. An implementer writes `func (f *FlagBase[T, C, V]) SchemaItemsType() string` in `flag_impl.go`, returning `""` when `T` is not a slice. A downstream consumer tests for array capabilities using standard Go idiom `if itemsTyper, ok := flag.(SchemaItemsTyper); ok`. The type assertion succeeds for every scalar flag (`IntFlag`, `StringFlag`, `BoolFlag`). The planned tests (`TestSchemaTypeBuiltins/scalars`) only check that `SchemaType()` returns scalar strings, completely missing that the scalar flag instances now satisfy `SchemaItemsTyper`.
**Impact:** `SchemaItemsTyper` ceases to be an optional discriminator. Every scalar flag falsely advertises collection capability to reflection and interface-driven schema generators.

## Challenge 2: Conflating JSON Schema primitive types with format attributes
**Framework:** SECOND-ORDER
**Failure scenario:** AC-1 specifies that temporal scalar flags must report categories `"duration"` and `"date-time"`. An implementer implements `SchemaType()` to return these strings verbatim. A downstream JSON Schema generator reads `st.SchemaType()` and assigns it to the JSON Schema `"type"` keyword (`{"type": flag.SchemaType()}`).
**Impact:** Generates invalid JSON Schema documents according to JSON Schema specifications (Draft 7, 2020-12, and OpenAPI 3.x), where `"type"` must be one of the primitive types (`string`, `number`, `integer`, `boolean`, `object`, `array`, `null`). In standard schemas, temporal values are `type: "string"` paired with a `"format"` attribute (`format: "date-time"` or `format: "duration"`). Any compliant downstream JSON Schema validator will reject the generated schemas as syntactically malformed.

**Impact:** Introspecting adapted third-party standard flags at application initialization either crashes the program with a nil pointer/interface panic or silently strips schema information for all uninitialized default flags.

## Challenge 4: Type erasure on nil and empty collections via shared value helper
**Framework:** INVERSION
**Failure scenario:** The spec chooses "one shared value-to-schema helper called by `FlagBase` and `extFlag`" that accepts `any`. To inspect slice item types from `any`, an implementer relies on runtime slice contents (`reflect.ValueOf(v).Index(0)`) or inspects `reflect.TypeOf(v).Elem()`. When presented with a nil slice getter (`extFlag` wrapping an uninitialized slice) or custom collection getter, passing untyped `nil` into `reflect.TypeOf(v).Elem()` panics. If the implementer catches this with a nil check, the helper cannot determine the element type of an empty or nil slice and returns `""`. The planned test `TestSchemaTypeBuiltins/arrays` passes because `FlagBase` has compile-time type `T`, but the mutation survives into `TestSchemaTypeExtFlag/collections_and_unknown`.
**Impact:** Adapted slice flags defined with nil defaults report `array` but drop their item types (`SchemaItemsType() == ""`), leaving schema generators unable to generate typed items schemas for empty default collections.
