**Important**

1. **`flag_schema_type.go:17-22` returns `"duration"` and `"date-time"`, which are not JSON Schema types** (important, 0.85).
 - The doc comment at `flag.go:114-118` promises a "JSON Schema type". The only valid values are null, boolean, object, array, number, string and integer.
 - `date-time` and `duration` are `format` keywords for strings. A consumer building `{"type": f.SchemaType()}` would produce an invalid schema, and strict validators (for example ajv, or MCP tool-schema checks) would reject it.
 - The tests assert these values (`flag_schema_type_test.go` "temporal/*"), so this looks intentional. The doc and the behavior still disagree, and this is exported v3 API.
 - **Fix:** return `"string"` and add a separate `SchemaFormater{ SchemaFormat() string }`, or reword the doc so it no longer claims these are JSON Schema types.

2. **Even as formats, the parsing rules don't match** (`flag_schema_type.go:17-22`) (important, 0.70).
 - `DurationFlag` parses Go syntax (`1h30m`) through `time.ParseDuration`. JSON Schema's `duration` format means ISO 8601 (`PT1H30M`).
 - `TimestampFlag` parses the layouts in `Config.Layouts`, not RFC 3339.
 - A schema-driven client (for example an LLM tool caller) would send values the flag rejects.
 - **Fix:** for Duration, report `"string"` with no format, or a Go-duration hint. For Timestamp, only report `date-time` when the layouts include `time.RFC3339`.
