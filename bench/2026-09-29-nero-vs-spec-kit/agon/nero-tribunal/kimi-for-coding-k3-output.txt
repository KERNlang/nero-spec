## 1. Critical Risks (must address before proceeding)

- **R1 — extFlag non-getter panic.** A runtime panic on a supported flag registration path directly contradicts AC-3's empty-fallback promise. Confirmed by two independent attackers.
- **R2 — undefined introspection source / lifecycle instability.** The spec's core mechanism is unspecified; this determines correctness of every acceptance criterion.
- **R3 — process violation on the OPEN finding.** The external-consumer gap must stay OPEN with an owner, and Confidence must drop below 0.90. This is a gating rule, not a judgment call.
- **R7 — vocabulary literals.** Cheap to fix, but shipping an interface contract without pinned return strings invites incompatible implementations.

## 2. Accepted Risks (acknowledged, acceptable)

- **R5** — interface-assertion ambiguity on scalars. The "both methods on all FlagBase instantiations" requirement is fixed; precise `""` documentation is sufficient mitigation for an additive optional interface.
- **R6** — GenericFlag non-delegation. Returns `""` per the spec's stated fallback; delegation is an enhancement that can follow.
- **R8/R9** — tooling and phrasing issues; editorial fixes during implementation.
- Defender's additive-compatibility argument holds: no existing implementer or caller breaks, and the "name collision" concern is correctly dismissed as harmless.

## 3. Overall Assessment

**Not safe to proceed as written; safe to proceed after targeted revision.** The additive design and shared-helper architecture are sound, and both attackers' highest findings converge on two concrete, fixable defects (R1, R2) rather than a flawed direction. The path forward:

1. Guard the `flag.Getter` assertion in `extFlag` and test the `AllowExtFlags` non-getter path.
2. Pin the introspection source (prefer the static type parameter `T`) and define pre/post-parse stability.
3. Restore the external-consumer finding to OPEN with an owner and reduce Confidence below 0.90.
4. Enumerate the exact vocabulary literals and add compile-time interface assertions for all `FlagBase` instantiations.

With those changes, the spec is ready for implementation; without them, it risks shipping a panicking public method and an unspecified core behavior behind an overstated confidence rating.
